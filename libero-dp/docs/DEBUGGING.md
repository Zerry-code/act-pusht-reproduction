# DP 低成功率排查：推导逻辑与实验记录

## 1. 问题与结果

本次目标是在固定的LIBERO抓碗任务、相同36条训练示范与9条验证示范上，找出Diffusion Policy低成功率的可验证线索，并得到能完成任务的策略。

最终组合方案在50个官方初始状态上成功42次（84%），在未参加小规模筛选的状态10–49上成功33/40（82.5%）。旧MIN_MAX 10k策略按本次显式状态协议复测为0/50。**结果证明组合方案在本次评测中有效，不证明某一个改动单独导致提升。**

原始证据：[旧模型50回合](../results/baseline50_raw.json)、[新模型筛选10回合](../results/screen10_raw.json)、[新模型确认50回合](../results/confirm50_raw.json)、[914帧验证](../results/validation_raw.json)、[数据审计](../results/data_audit_raw.json)。

### 证据如何区分

- 本次上传的JSON、配置和脚本按原字节收录，见[来源清单](../results/source_manifest.json)。50回合总数、成败、状态ID、种子和夹爪反转中位数均可从这些JSON重算。
- 前期试验和12帧抽样诊断值来自实验期间保存的运行输出与结项报告；相应旧诊断原始文件不在本次提交中，下面标为“历史记录”，不冒充已重新运行或完整独立验证。
- 视频中的动作现象是辅助线索，不能单独证明控制错误的根因。网页协作会话没有本机GPU访问权；后期实际训练与仿真由本地Codex在实验者电脑执行。

## 2. 固定任务，先防止比较对象发生变化

- 数据：`lerobot/libero`，revision `a1aaacb7f6cd6ee5fb43120f673cebb0cfea7dd4`，10FPS。
- 数据集任务34，对应仿真`libero_spatial`任务0：`pick up the black bowl between the plate and the ramekin and place it on the plate`。
- 训练36条/3573帧，验证9条/914帧；按完整episode划分，避免把同一示范的相邻帧分别分到训练和验证。
- 输入为两路图像和8维状态；输出为7维相对控制动作，不能把状态维数理解为8个受控自由度。
- 状态和动作的归一化统计只来自训练划分；训练样本的当前观察与从该时间步开始的动作窗口对应，窗口不能越过episode边界。

固定的[划分文件](../config/libero_task34_split.json)记录全部episode ID。仿真初始状态的筛选/确认划分与示范训练/验证划分是两套不同的划分，不能混称。

## 3. 最初失败：先检查数据处理，再谈训练量

### 3.1 现象

历史早期DP采用48步窗口、执行10步、DDIM推理10次、状态/动作MEAN_STD且关闭去噪样本裁剪。正式50回合结果为2/50（4%）。视频表现为抓空、运动不准确。

### 3.2 假设与验证

优先区分：动作归一化/反归一化错误，还是模型生成动作不准确。在同一个验证观察上，先将示范动作归一化再还原，再固定种子分别生成动作。

历史记录显示，归一化往返误差约3×10^-8，数值还原基本正确；但DDIM100次去噪时首步输出出现约29、81及夹爪-486等异常量级。DDIM10次没有同等程度爆炸，但预测仍不准确。

### 3.3 当时的结论与修正

这说明“增加去噪次数”不是直接修复，且不裁剪的生成路径出现了数值失稳。它不证明归一化是所有低成功率的唯一原因，也不说明MEAN_STD对所有DP都不适用。

最初为与ACT保持一致而直接复用MEAN_STD，是一次需要修正的工程选择。随后改为LeRobot DP默认的状态/动作MIN_MAX配合`clip_sample=True`，只从训练集重算min/max，并重新训练10k；图像继续使用ImageNet均值/标准差。

新模型的归一化往返误差仍约1e-7，DDIM100不再出现极大输出，但10回合只有1次成功。**裁剪约束了数值范围，不等于学会了抓取。**

## 4. 控制变量检查采样器与执行长度

先固定10k MIN_MAX权重，在同一组12个验证时间步和固定随机种子上比较生成动作。下表为历史记录，误差采用MIN_MAX归一化坐标。

| 采样方式 | 首步动作MAE | 夹爪MAE |
|---|---:|---:|
| DDIM 10次 | 0.2790 | 0.3609 |
| DDIM 25次 | 0.2931 | 0.4554 |
| DDIM 50次 | 0.3178 | 0.6793 |
| DDIM 100次 | 0.3482 | 0.8978 |
| DDPM 100次 | 0.2089 | 0.2559 |

推导：这批样本上更多DDIM迭代反而误差更大，因此不继续增加DDIM次数；DDPM离线误差较低，值得进入仿真，但离线误差不能代替任务成功率。

随后进行历史10回合小试：

| 权重 | 采样器 | 每次执行动作数 | 成功 | 用时 |
|---|---|---:|---:|---:|
| MIN_MAX 10k | DDIM10 | 10 | 1/10 | 245.10秒 |
| 同上 | DDPM100 | 10 | 2/10 | 387.47秒 |
| 同上 | DDPM100 | 5 | 2/10 | 571.26秒 |

缩短执行长度的假设是：更频繁地基于新观察重新规划，可能减少连续执行中的误差积累。此次从10缩到5没有观察到成功回合增加，却增加了计算时间，因此不继续沿这个单变量方向扫描。2/10与1/10只有一次成功的差异，不足以证明稳定提升。

这里改变的是重新规划间隔，不是相机在环境步之间停止采集；策略仍接收观察，但动作队列非空时沿用已生成的动作。

## 5. 训练是否不足、是否过拟合

对训练/验证各固定抽样12个时间步，进行相同噪声种子的检查，得到历史记录：

| MIN_MAX 10k | 训练抽样 | 验证抽样 |
|---|---:|---:|
| 有效位置噪声MSE | 0.05020 | 0.06354 |
| MIN_MAX尺度首步动作MAE | 0.26171 | 0.27897 |
| 归一化还原最大误差 | 约9×10^-8 | 约9×10^-8 |
| 参考动作越界比例 | 0 | 0 |

解释：这批样本上没有看到训练明显好、验证极差的强过拟合迹象；训练样本上的动作预测也有偏差。但样本只有12帧，不能据此排除所有泛化或数据处理问题。

为检验单纯增加更新数是否有帮助，加载10k权重和AdamW状态，保持设置继续到20k。没有恢复RNG和DataLoader位置，因此不是逐位复现连续20k训练。

- 10k末尾20步平均loss约0.0550；20k约0.0546。
- 20k、DDPM100、执行10步的小试为0/10。

结论：没有获得继续增加训练次数的正面证据。末尾20步loss不是完整学习曲线，0/10与2/10也不能严格证明训练一定退化；停止盲目堆步数，继续定位。

## 6. 检查视觉前处理、BatchNorm和图像条件

### 6.1 是否把目标裁掉了

读取模型实际配置：`resize_shape=None`、`crop_shape=None`。虽然`crop_is_random=True`，但没有启用裁剪。因此“默认的小裁剪窗口截掉目标”没有得到当前配置支持。

### 6.2 BatchNorm的训练/评测统计是否明显失配

模型含20层BatchNorm，训练batch只有2，值得检查保存统计量与当前批次统计量的差异。

在20k模型、相同12个验证时间步和相同噪声种子上，只切换BatchNorm统计方式，不更新权重，并在结束时恢复缓冲区。历史MSE分别为0.0597935与0.0596176，差异约0.3%。

结论：这项检查没有显示大幅统计失配，不把它当作已经定位的主要根因；也不能由此推断BN在所有设置下都没有问题。

### 6.3 模型是否只沿着大致轨迹走、没有利用图像

旧20k的两段失败视频显示：机械臂先接近碗，再向盘子附近移动，没有观察到碗被持续夹持搬运，后段还可能碰动盘子。这个现象提出了“视觉条件不足”的假设，但不能仅凭动作外观认定模型忽略视觉，也不能确定闭合过早或接触失败的具体原因。

对照方法：固定state、参考动作、模型、噪声种子，只将两路相机一起置换为其他验证时间步的画面。历史记录如下：

| 20k模型输入 | 噪声MSE | 首步动作MAE | 夹爪MAE |
|---|---:|---:|---:|
| 正确图像 | 0.05979 | 0.20323 | 0.29017 |
| 置换图像 | 0.07006 | 0.31414 | 0.45365 |

平均预测变化为0.21039，正确图像产生更低误差。**这批样本支持视觉条件有用，“完全忽略图像”不再是优先解释。** 它仍不能证明视觉定位已足够准确；置换输入也不再是原示范中的一致观察。

## 7. 从夹爪和数据审计形成更具体的线索

[数据审计](../results/data_audit_raw.json)显示，训练动作中开合标签为-1与+1，分别1849和1724帧；验证分别476和438帧，不是极端单类别数据。

示范的夹爪动作通常只有少数阶段切换。与之相比，旧模型的实际执行命令频繁变号，符合抓取阶段不稳定的现象。评测命令的反转指标定义为相邻`sign(g)`不同，精确0也作为一种符号；不能直接把它等同于物理夹爪接触或抓牢状态。

长窗口还带来较多尾部填充：训练集48步窗口中，约47.36%的起点含填充，动作位置的填充比例约23.68%；16步分别约15.11%和7.56%。遮罩已排除填充位置损失，因此这不是已经证明的跨episode错误，但它提供了缩短预测范围、减少无效位置的工程动机。没有做单独窗口消融，不能认定它就是低成功率根因。

## 8. 复核训练方案，并采用一组明确记录的改进

原始DP训练方案采用GroupNorm与EMA。复核时发现原始配置明确提醒EMA与BatchNorm组合可能损害性能。因此撤回先前“直接给现有BN模型加EMA即可修复”的建议，不将缺少EMA当作已确认根因。

参考：[原始DP配置](https://github.com/real-stanford/diffusion_policy/blob/5ba07ac6661db573af695b419a7947ecb704690f/diffusion_policy/config/train_diffusion_unet_image_workspace.yaml#L105)、[原始EMA实现](https://github.com/real-stanford/diffusion_policy/blob/5ba07ac6661db573af695b419a7947ecb704690f/diffusion_policy/model/diffusion/ema_model.py)。

在需要得到可用工程基线的目标下，最终组合调整如下；这不是逐项严格消融：

| 因素 | 旧MIN_MAX 10k | 新4k候选 |
|---|---|---|
| 观察历史 | 1步 | 1步，保持不变 |
| 动作预测窗口／执行长度 | 48／10 | 16／4 |
| 图像编码输入 | 256×256 | 128×128 |
| ResNet18初始化 | ImageNet | 随机初始化 |
| 编码器归一化 | BatchNorm | GroupNorm |
| U-Net通道 | 256/512/1024 | 128/256/512 |
| 扩散训练目标 | 噪声epsilon | 干净动作sample |
| EMA | 无 | 0.995，保存EMA权重 |
| 更新数／batch | 10000／2 | 4000／8 |
| AdamW betas | 0.9,0.999 | 0.95,0.999，fused |
| 训练数值路径 | FP32 | BF16 autocast，显式TF32设置 |
| 图像读取 | 逐样本解码 | 按示范解码、缩放并缓存uint8图像 |

学习率1e-4、weight decay 1e-6、梯度裁剪1.0、训练划分和MIN_MAX处理保持一致。最终采样仍为DDIM10，100个训练扩散时间步。

关键解释：

- `prediction_type="sample"`表示网络在加噪动作条件下预测干净动作；推理仍从噪声开始，经扩散采样器多轮生成动作，不是换成了普通单次回归策略。
- 新模型通过`DiffusionPolicy(config)`重新初始化训练。脚本读取旧目录的配置和统计，不加载旧策略权重，不能称为从旧10k或20k继续微调。
- 4000×8=32000次样本抽取，旧10000×2约20000次，因此“更新次数更少”不代表看过更少训练样本，不能据此断言样本效率更高。
- 训练配置里保留cosine/warmup预设字段，但实际脚本没有学习率调度器；不要把配置字段误写成实际执行行为。
- 由于多项共同改变，当前证据不能把提升单独归因于EMA、GroupNorm、窗口、直接预测干净动作或更大的batch。

## 9. 固定候选后，正式确认结果

[评测脚本](../scripts/eval_dp_libero_grasp.py)逐个指定官方`pruned_init`文件的状态索引。使用relative控制、256×256双相机原始观测，成功定义为首次结束步之前或当步出现环境成功信号；状态ID不是数据集episode ID。

| 运行 | 状态ID | 环境种子 | 成功 |
|---|---|---|---:|
| 旧10k正式对照 | 0–49 | 1042+状态ID | 0/50 |
| 新4k筛选 | 0–9 | 42+状态ID | 10/10 |
| 固定新4k正式确认 | 0–49 | 1042+状态ID | 42/50 |
| 正式确认的未筛选子集 | 10–49 | 同上 | 33/40 |

正式确认中状态0–9为9/10，不是筛选时的10/10。确认失败状态为3、10、18、23、24、26、47、49。完整逐回合结果见原始JSON；[验证脚本](../scripts/verify_results.py)核对状态覆盖、种子、汇总和反转指标。

旧模型按5个环境成批，新模型逐回合运行。虽然状态ID及环境种子匹配，`set_seed`的调用和扩散随机数流分组不同，所以不能声称随机过程完全匹配。正式确认包括参加过筛选的10个状态，较独立的子集结论是33/40；这一状态划分也不证明与训练场景独立。仅有一个训练种子，没有多种子统计。

## 10. 用独立示范指标交叉检查抓取阶段

[留出示范验证](../results/validation_raw.json)在全部9条示范、914帧上运行，seed=137；输入真实示范观察，生成首步动作，反归一化后与示范比较。它不同于前期12帧诊断，不应混用样本数或误差尺度。

| 指标 | 旧10k | 新4k |
|---|---:|---:|
| 原始动作数值尺度的首步MAE | 0.24675 | 0.10694 |
| 夹爪符号准确率 | 74.40% | 92.01% |
| 闭合召回率 | 289/438，65.98% | 418/438，95.43% |
| 开启召回率 | 82.14% | 88.87% |
| 距示范切换前4步以内的90帧符号准确率 | 48.89% | 67.78% |

闭合定义为最后一维动作大于0。符号准确率不是物理抓取成功率；MAE混合了不同控制维度，不是米或角度，也不能和ACT的标准差归一化MAE直接比较。

仿真50回合中，每百步夹爪命令反转次数的回合中位数由10.71降为1.33。计算为每回合`100×反转次数/首次结束步数`，再取中位数；示范约2.2作为行为参考，其轨迹长度与仿真分布不同。

推导：离线夹爪指标、闭环命令稳定性与任务成功率的改善方向一致，支持“旧策略抓取阶段的夹爪预测不稳定是重要失败线索”。它仍然是关联证据，不是单独夹爪消融；低反转本身也不是充分条件，例如正式失败状态49只有2次反转。

## 11. 排查结论与尚未完成的验证

**已确认：** 本次组合方案在指定50个初始状态上获得42次成功；单纯增加去噪次数、单独缩短旧模型执行长度及旧模型续训的小规模尝试没有显示可靠收益。新策略利用了相同示范划分，夹爪预测与闭环表现共同改善。

**不能确认：** 某一个参数是唯一根因；DP总体优于或劣于ACT；84%是整个Spatial套件或未见场景泛化性能；4k更新代表更低训练样本量；减少夹爪反转一定能成功。

**仍需补齐：** 多训练种子、统一batch及随机数控制的对照、逐项消融、原始环境依赖锁，以及最终模型演示录像。最终模型的原50回合没有录像，历史旧视频不能用作新模型演示。

本次报告基于实测记录与上传证据整理，未更改环境成功阈值。排查有人工学习和AI协作；不将工具辅助工作包装成个人独立提出算法。
